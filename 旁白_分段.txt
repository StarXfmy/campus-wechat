===== 第 1 段 · 开场 + 架构（285 字）=====
这是我做的校园木鱼的微信端。在微信群 @ 一下，就能查课表、找空教室、看校园卡花了多少钱。

它和飞书端共用同一颗大脑：二十多个校园工具、规则路由、Agent 兜底，只有一份 Python 代码。飞书端直接用，微信端通过本机一个 HTTP 接口调用它。所以飞书加了新功能，微信这边自动就有。

微信端要解决的是另一件事：同学都在微信群里，而微信没有给个人号开放任何机器人接口。

所以这一端的主体工作，是在不注入、不改客户端、不读内存的前提下，把「读消息、想一想、打字发回去」这条链路做稳。链路三个进程：微信、我写的 Python 桥接、校园大脑。中间那层 Node 骨架已经下线。

===== 第 2 段 · 私聊演示（259 字）=====
私聊挑几条有代表性的。

问这周花了多少，它去查校园卡流水，按天汇总，算出常去的店。明天几点上课在哪，走课表。快递在哪取，走的是从宿舍楼群通知里一条条整理出来的知识库，带出处。绍兴这周天气，七天的预报都能给。

「奶蛙」这种它不认识：不硬编答案，先承认不知道，再真的联网去搜，回答末尾标注这是搜来的。

设提醒也做了。三十秒后提醒我洗衣服，到点它主动发消息过来——这是微信端唯一保留的主动消息，早报和二课推送都放回飞书了。

新加的是发邮件：说清收件人、主题、内容，它先出预览；回一句「发送」才真发。微信没有卡片按钮，确认就用一句话。

===== 第 3 段 · 群聊 + 防封号设计（248 字）=====
群聊这段是花心思最多的地方：让它能说话不难，让它少说话才难。

第一条，不 @ 也不提它名字，它真的不回。第二条，@ 了才回，而且控制在七十字以内。

这些不是靠提示词求模型克制，是代码开关：只认 @、引用它的消息、或正文里出现「木鱼」；两次回复最少隔三十秒，冷却期内的提问排队补答、一条不丢——主人不受这条限制。回复前按长度随机等二到十二秒；每小时最多四十五条。连主人在群里不 @ 也不回，避免「主人在就特别活跃」的模式。

秒回、连发、深夜在千人群里说话，这些是机器的特征。它要想像人，就得有人类的迟钝。
===== 第 4 段 · 看图、语音与红包（263 字）=====
微信端有两个飞书端没有的东西。

一是看图。微信存图片用的是 wxgf 容器，里面是 HEVC 编码，不是标准 JPEG。一开始按扩展名判断格式，把 wxgf 当 JPEG 发给视觉接口，结果就是「有时能认、有时不能」。后来改成按文件头判格式，认出 wxgf 先转码再发。

二是语音。发一段语音过去，本机转成文字再回答，不走云端，零成本。

还做了红包提醒：群里来了红包，它只喊一嗓子，不点、不领、不分析。自动领红包是明确违规的事，这条线划得很清楚。

新补的一条是隐私：不是主人的人私聊问课表、余额，它一律不答——那些数据其实都是主人的。

===== 第 5 段 · 收尾 + 局限（295 字）=====
最后说清楚它不行的地方。

电脑必须开着、微信窗口不能挡，人不在就不上线。发消息慢，一条两到十二秒，因为要真的打字。有封号风险——微信不开放个人号机器人接口，那些克制只是把风险往下压，压不到零。

最大的收获不是接上微信，是修 bug。有个调试代码引用了别的作用域变量，链路停摆半个月，异常还被上层吞掉。有改了配置还不认主人的——历史里几十条「你不是主人」，模型顺着旧回答否认。

今天又补两个：天气区间被清洗删掉波浪号，十二到二十度变成幺二二零度；群里主人被判成非主人，因为拿群号去比主人 wxid。

这些让我明白：行为不只由配置决定，还由喂给它的上下文和中间层决定。这就是校园木鱼的微信端，谢谢观看。
